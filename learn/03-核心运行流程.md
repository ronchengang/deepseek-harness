# 核心运行流程（Turn / Step / 会话日志）

> 这是 dsh 跑一个任务时真正发生的事。权威来源：`docs/architecture.md` 的 Turn flow 一节，以及 `packages/core/agent-loop`。

## 三个基本概念

- **step（步）** = 一次模型请求 + 它调用的那些工具。
- **turn（回合）** = 零或多个 step：在它第一个输入被认领前开启，在「无事可做」后关闭。
- **session（会话）** = 一条**只追加（append-only）的 `SessionEvent` 日志**，是模型所见上下文的唯一来源。

## 事件是扩展点（三个域）

改动 dsh，第一步往往是选对事件域：

1. **Session 事件** — 追加进日志的持久事实，通过 `session/event` 广播。当这个事实必须跨 reload 存活时用它。
2. **Agent 事件（`agent/*`）** — 携带一个活跃 `Agent`：inbox、step、status、request、validation、continuation。用来观察或拦截进行中的工作。
3. **Capability 事件** — 把策略和适配器挂到某个 seam 上（`fs/*`、`tools/*`、`telemetry/*`），不需要 import 主循环。

完整的事件生产者/消费者表在 `docs/event-producer-consumer.md`。

## Turn 流程（简化版）

```text
turn/start
  认领下一个 step 的输入 + 一条排队消息
  快照 Session 的模型选择；组装 prompt 片段 + 本 step 准入的工具 schema
  -> agent/pre-step（可接受 / 改写 / 拒绝认领的消息）
     被拒绝、或首个认领被改写为空 -> 不产生 step，直接关闭 turn
     step/start
     agent/request -> prepareCall（取消则 system 和 user 都不提交）
     把准入消息作为 user/message 追加；协调保留的运行时上下文
     按需记录 request/header 和 request/context
     从日志推导并冻结模型历史
     流式发送绑定好的请求 -> llm/stream -> agent/assistant-stream start
       agent/assistant-stream chunk*
       assistant/message | assistant/attempt -> agent/assistant-stream end
     tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*
     step/end
     工具还要再请求一次，或下一个 step 的输入到了 -> 认领 -> 下一个 step
  -> agent/turn-stopping
turn/end
```

### 哪些是持久事件，哪些是活扩展点

- **持久 session 事件**：`turn/*`、`step/*`、`system/message`、`user/message`、`assistant/message`、`assistant/attempt`、`tool/*`。
- **活扩展点**：`agent/pre-step`、`agent/request`、`llm/stream`、三个 `tools/*` 是 **waterfall**（监听器必须调 `next()` 委托）；`agent/turn-stopping` 是 **serial**，没有 `next()`。
- `agent/assistant-stream` 发布进程内的 start / chunk / end 帧，Web 的 Session-follow 适配器是这个活事件唯一的远程消费者。

## 会话日志（source of truth）

- `deriveMessages()` 从日志投影出模型历史。
- 每个 `assistant/message` 内嵌生成它的那段精确压缩流；`assistant/attempt` 保留失败/重试/取消/流错误的尝试，但**不加入模型历史**。
- Fork、resume、transcript、遥测、持久化 全都从这些持久 settlement 推导；实时 UI 增量来自 `agent/assistant-stream`。

### 铁律：模型可见 ⟺ 已记录

> **任何到达模型请求的东西，都必须能从 session 日志重建。** 新的模型可见输入，必须对应一个 session 事件。

这是整个仓库最重要的约束之一（AGENTS.md 多处强调）。

## 会话格式版本

- 只在「现有判别式无法阻止不安全解释」时才 bump `SESSION_FORMAT_VERSION`；同版本内的改动要求 reader 行为安全。
- 已提交的代（generation）路径**永不**重命名、替换或删除。
- 相邻迁移（adjacent migration）每个包只负责一个 `vN -> vN+1` 步骤。
- SQLite 用单调递增的 `SCHEMA_VERSION`。

## 新行为该挂在哪（速查）

| 目标 | 机制 |
|---|---|
| 加一个模型 provider | 在 `ctx.llm` 注册它的适配器 |
| 加一个面向模型的能力 | 在 `ctx.tools` 注册；它的 schema 加入 prompt 组装 |
| 加 shell 执行 | 注册一个 `ctx.shell` 后端 |
| 拦截请求/工具/回合 | 用对应的 `agent/*` 或 `tools/*` 事件 |
| 加模型可见上下文 | 调 `agent.inject()`，它落在下一次准入的请求里 |
| 加持久会话状态 | 扩展 `SessionEventMap`，从日志渲染和回放 |
| 把会话存进新后端 | 在共享 handle 脚手架上实现 `SessionPersistence` |

> 原则：**新行为上插件，别改循环**。改 `agent-loop` 本身需要同步更新 `docs/architecture.md`。
