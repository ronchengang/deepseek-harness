# 包结构（packages/ 分组导览）

> dsh 由 `packages/<group>/<pkg>/` 下的一堆 npm 包组装而成，每个包都属于**唯一一个**能力族（group）。权威地图在 `packages/README.md`，每个 group 的 README 是该族包列表的权威来源。

## 核心骨架（core/）

产品 API 的脊梁，也是读代码最该先看的地方：

| 包 | 职责 | `ctx` key |
|---|---|---|
| `core/session` | 只追加（append-only）的 `SessionEvent` 日志 + 内存存储 | `ctx.sessions` |
| `core/system-prompt` | Prompt 片段 + 工具 schema 的组装 | `ctx.systemPrompt` |
| `core/tools` | 作用域工具注册表 + 受保护的执行管线 | `ctx.tools` |
| `core/agent` | `Agent` 接口、活跃注册表、`agent/*` 事件 | `ctx.agents` |
| `core/agent-loop` | 实现 Agent 接口的**默认驱动器**（主循环） | `ctx.agentLoop` |
| `core/scope` | 每个 agent 的作用域注册原语 | 库，无 key |
| `llm/llm` | 消息/流式词汇 + 适配器 seam | `ctx.llm` |

`core/` 下还有 `agent-default-model`、`agent-tool-presentation`、`tool-executor-native`、`tool-executor-ptc` 等。

## 能力族分组（按职责归类）

### 执行与环境
- `shell/` — Bash 能力族：执行器 seam + 本地实现 + 模型可见工具
- `subprocess/` — 子进程能力族：定义 + 本地进程树 provider
- `terminal/` — 持久 PTY 服务
- `ptc-runtime/` — PTC 执行能力族
- `fs/` — 文件系统能力族：seam + 本地实现 + 文件工具 + 发现工具
- `lsp/` — LSP 能力族
- `sandbox/` — 进程封闭 seam（bwrap / Landlock / Seatbelt 后端）
- `ssh/` — POSIX 远程连接（配套 fs / subprocess / sandbox provider）

### 模型与工具
- `llm/` — LLM 能力族：抽象服务 + 各 provider 适配器
- `mcp/` — 外部 MCP（Model Context Protocol）服务器暴露为原生工具
- `skill/` — 技能能力族
- `todo/` — 模型可见的 `todo_write` 工具
- `web/` — Web 能力族：seam + 搜索/抓取 provider + 工具
- `workflow/` — 工作流 seam + PTC 进程引擎 + `workflow` 工具
- `computer-use/` / `browser-use/` — 独占命名的桌面 / 浏览器 provider 注册

### Agent 协调
- `subagent/` — 子 agent 能力族：provider 注册契约 + 委派工具
- `jobs/` — 通用后台任务运行时 + 任务控制工具
- `goal/` — 同会话目标持久化
- `plan/` — 计划协作状态
- `preset/` — 每会话 agent 组合（来自 preset 的 `cordis.yml`）
- `guard/` — 循环卫生守卫（重复调用提醒 + 执行超时强制）
- `compaction/` — 上下文压缩能力族
- `context/` — 模型可见的请求上下文（工作区指令、时间、引用）

### 数据与持久化
- `session/` — 持久会话数据平面：持久化 seam + 后端 + 投影 seam + 标题 + 报告
- `session-query/` — 会话检索族（逻辑语料、有界读取、血缘、语义过滤、SQLite 全文检索）
- `attachment/` — 附件标识、校验、本地内容寻址存储
- `spill/` — 溢出（spill）能力族：存储 seam + 工具结果溢出策略
- `storage/` — 非会话存储中心 + 后端
- `workspace/` — 工作区实体
- `deliverables/` — 回合交付物（文件交付 + 工作区变更记录）

### 远程 / 应用层
- `api/` — 远程 BFF 组装 + Typert RPC 网关
- `typert/` — 类型图生成、产物加载、运行时注册表
- `sdk/` — 进程外 SDK：JSON-RPC 协议 + TS 客户端/服务端
- `acp/` — 仅自动化的 Agent Client Protocol 服务器
- `boot/` — 共享的 app-bin 启动胶水
- `host/` — Web GUI host 服务（目录选择、应用启动、插件清单、遥测）
- `client/` — Web GUI 浏览器侧：shell、wire、对象服务、slot、`ui-*` 插件
- `bundle/` — 可安装的 `dsh --profile` 补丁层

### 支撑
- `interaction/` — 人机协作平面：审批/交互 seam + 权限预设 + ask-user 工具
- `credentials/` — 凭证引用/记录 seam + env-over-`.env` provider + 授权流
- `settings/` — 用户设置 seam + 文件后端
- `identity/` — 共享匿名身份
- `feedback/` — 人类反馈捕获
- `telemetry/` — 共享 Cordis OTel 上报通道
- `extensions/` — Agent 运行时自我修改（实时插件/服务检视 + 模型写的挂载/卸载）
- `document/` — 共享的 Host Office 转 PDF
- `experimental/` — 评估中的能力（状态和支持策略独立）
- `test-support/` — 测试基建（testkit、replay、Loader 冒烟测试）
- `util/` — 零依赖底层工具（`Branded<B>`、home/path 辅助、timeout、retention、官方 bundle 列表）

## 关键概念：能力 seam（capability seam）

一个 **seam** 是可替换的能力，由三个角色组成：

1. **Service Definition** — 声明接口
2. **Service Provider** — 实现接口
3. **Consumer** — 使用接口（通常是面向模型的工具）

一个包可以身兼多角色，但**单独一个角色不构成 seam**。新增一个能力意味着三个角色都要设计。这就是「换一个 provider 改变整个产品」的机制来源。

## Profile 与 Bundle

- **profile（配置档）**：存在 Harness home 里的命名组合，列出它叠加的 bundle。模板有 `web` / `headless` / `sdk` / `sdk-minimal` / `acp`。
- **bundle（分发包）**：Cordis 配置行 + 它挂载的代码的分发格式，保证上层仍可打补丁（patch）。
- 都在各自 `package.json` 的 `dsh` 字段声明：`dsh.profile` 列出 profile 的 bundle，`dsh.bundle` 指向 bundle 的补丁文件。
- `dsh-base` 是 `web`/`headless`/`sdk`/`acp` 共享的第一层。

看自己机器实际启动的插件树：

```sh
dsh --profile web --dump-config
```
