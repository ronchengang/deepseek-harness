# 开发与测试（命令、门禁、约定）

> 来源：根 `AGENTS.md`、`docs/development.md`、`docs/testing.md`、`package.json` 的 scripts。

## 环境要求

- Node >= 24.9
- pnpm 11.28.5（仓库用 pnpm workspaces）
- 全 ESM 项目

## 常用命令

```sh
pnpm install            # 安装依赖
pnpm run clean          # 清理构建产物
pnpm run build          # build:artifacts + build:check（并发）
pnpm run build:artifacts # 只出产物：tsc 产 lib/types，tsdown 打运行时，Web
pnpm run build:check    # 用当前 build:artifacts 产物对聚合测试/脚本做类型检查

pnpm run typecheck
pnpm run lint
pnpm run duplication    # 跨文件 TS 克隆检测

pnpm run test           # 单元测试（vitest run）
pnpm run test:coverage  # CI 覆盖率门禁：packages/*/*/src 每文件 100%
pnpm run test:e2e       # 真实 API 测试；无 DEEPSEEK_API_KEY 时自跳过
pnpm run test:snapshot  # 无 key 的录制会话回放，走 shipped profile；过滤：-t <name>
pnpm run test:snapshot:record  # 重录期望输出（需要 key）

pnpm run hygiene        # publint + 工作区/包/依赖检查 + NodeNext consumer 检查
pnpm run doc-sync       # 文档门禁（scripts/run-gates.ts）
pnpm run test:docs      # 快速文档检查（不构建）
pnpm run website:build  # VitePress 构建（兼做死链检查）
```

### 从源码跑一个任务（需要 DEEPSEEK_API_KEY）

```sh
pnpm dsh --profile headless "task"   # 跑一个任务
pnpm run demo:ptc -- "task"          # headless PTC 模式
pnpm run dev:web                     # 构建 + 启动 Web，源码改动时重建 client bundle
```

## 测试体系要点

- **`test:coverage` 才是 CI 覆盖率门禁**，不是 `test`。覆盖率要求 `packages/*/*/src` 每文件 100%。
- 测试放在包级 `tests/` 目录，不是 `src/__tests__/`。
- **测试描述行为，不是正确性**。行为过时就连同测试一起改，并在 PR 里说明原因。
- **产品可见的插件需要非单元的「真实组合」测试**：通过 Loader 和 app/process 启动一个 test-only 的 `cordis.yml`，只 mock 外部服务或不确定输入，断言模型可见/持久/用户可见的输出。手搭 `ctx.plugin(...)` 的套件不够。
- 每个非平凡的「模型可见或产品用户可见」改动，都要更新一个无 key 的录制会话快照。
- **两个 SDK 都投影主循环**：agent-loop / session-lifecycle / `SessionEventMap` 的改动，要在同一个 PR 里更新 TS 和 Python SDK 的期望输出。
- 快照 fixture 在 macOS/Linux 回放；修 fixture，不要修 normalizer。

## 推送前

遵循 `.agents/skills/dsh-pre-push-checks/SKILL.md`，只报告实际跑过的命令。原则：

- 按改动的面匹配证据：聚焦行为测试、模型/用户输出快照、文档改 `doc-sync`、发布路径跑构建冒烟、provider 跑真实 API e2e。
- **不要默认跑全量套件**，也不要为了 commit/push 重复跑已通过的检查。CI 负责穷尽覆盖和平台矩阵。

## 关键编码约定（高频踩坑点）

- **全 ESM**：跨包用包名导入，本地相对导入用 `.ts` 后缀。不能有 CJS-only 导出。
- **注册是副作用**：一切贡献走 `ctx.effect()` / `ctx.on()`，`register()` 返回 disposer。
- **类型化事件用声明合并**：事件 JSDoc 需要 `@mode` 和 payload `@param`；公开服务方法要文档化参数和非 void 返回值。
- **在判别标签上 switch**：封闭 union 以 `assertNever` 收尾；可扩展 union 走文档化的默认分支。
- **Waterfall 监听器必须调 `next()`** 才能委托；不调直接返回会短路整条链。
- **模型可见 ⟺ 已记录**：到达模型请求的一切都要能从 session 日志重建；新模型可见输入要有 session 事件。
- **插件优先，别改循环**：新行为挂在文档化的扩展点上；改 `agent-loop` 要更新 `docs/architecture.md`。
- **包边界显式 > 隐式**：默认值是实现里显式的 `resolve(request): Spec` 步骤，不是 `run()` 里藏的 `?? default`。
- **插件里不要硬编码可调参数**：随部署变化的选择是校验过的 `Config` 字段，能从 cordis.yml 改。协议常量、外部规范、安全不变量保持固定。
- **跨边界的不透明 id 要 brand**（`Branded<B>`，来自 `dsh-brand`），不用裸 `string`。
- **在类型化同进程边界信任 TypeScript**：不要只为静态接口已要求的值加运行时校验。校验只在 parser/config、队列、模型/工具 JSON、持久/文件、worker、进程、wire 这些边界做。
- **不新增 `as unknown` / `<unknown>` 断言**。
- **文件以恰好一个尾随换行结束**（pre-commit 门禁 `git diff --cached --check`）。
- **源平面 vs 产物平面不混**：静态门禁和测试通过 tsconfig `paths` 把工作区导入解析到 `src`。

## 文档与 Agent Notes

- 代码改动必须同步更新受影响的 README 和 JSDoc 契约。
- 只为「持久的决策理由」写 Agent Note（`.agents/notes/`）；机械/局部编辑免写。归档的 note 是冻结历史，不是当前权威。
- 外部可感知的破坏性变更要立刻记进 upgrade guide。
- 文档描述当前状态，不写历史/状态标注（历史放 commit / PR / Agent Note / postmortem）。
- 每段一个物理行（`verify-md-wrap`）；有字数预算门禁 `verify-doc-budgets`。

## 密钥 / .env

- 真实 API 测试和 demo 读 `DEEPSEEK_API_KEY`、可选 `DEEPSEEK_BASE_URL`、以及根 `.env`。
- **绝不提交凭证**。CI e2e 无 key 时自跳过。
