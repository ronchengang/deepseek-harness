# DeepSeek Harness 项目概览

> 学习笔记 · 基于仓库扫描整理。这个目录的所有内容都是「学习笔记」，不是项目官方文档，不受 `docs/` 的文档规范约束。

## 一句话定位

DeepSeek Harness（简称 `dsh`）是 DeepSeek AI 开源的 **Agent 运行框架（agent harness）**，用来驱动大模型自主完成任务。它最核心的设计理念是 **「一切皆插件」（everything-is-a-plugin）**。

- 包名前缀：`@deepseek-ai/dsh-*`
- 当前版本：`0.2.2-alpha.2`（开发者预览期，会有破坏性变更）
- 许可证：MIT
- 底层框架：[Cordis](https://github.com/cordiverse/cordis)（被 vendor 进仓库，见 `vendor/`）

## 为什么是「一切皆插件」

传统框架通常有一个「内核」，你只能在它周围打补丁。dsh 没有特权内核：

- 模型适配器、工具注册表、会话日志、**甚至 Agent 主循环本身**，全都是插件。
- 每个插件通过 **Cordis 的上下文（context）** 向共享环境贡献「服务（service）」「类型化事件（typed event）」和「可撤销的副作用（reversible effect）」。
- 想扩展功能？不是改内核，而是「在旁边再挂一个插件」。插件卸载时，它注册的东西会自动撤销。

这带来一个关键特性：**换一个 provider 就能改变整个产品行为**。比如把文件系统和子进程的 provider 指向远程沙箱，Bash、PTY、LSP 全都跟着搬过去，无需 fork。

## 顶层目录速览

| 目录 | 作用 |
|---|---|
| `packages/` | 核心所在。所有 `@deepseek-ai/dsh-*` 工作区包，按能力族分组（见 `02-包结构.md`） |
| `apps/` | 可运行的应用：`cli`、`web`、`desktop`、`desktop-host`、`plugin-market-generator` |
| `vendor/` | 被 vendor 进来的 Cordis 源码（固定版本的源码拷贝） |
| `native/` | `@deepseek-ai/node-addon-system` 原生插件源码 |
| `python/` | Python SDK / 运行时 |
| `docs/` | 官方文档（中英双语，有严格的文档规范和字数预算） |
| `.agents/` | 给 AI agent 看的工作流、笔记（notes）、技能（skills） |
| `scripts/` | 各种校验门禁（gates）和生成器 |
| `benchmarks/` | 性能门禁 |
| `website/` | 基于 VitePress 的文档站投影 |
| `snapshots/` | 会话快照测试数据 |

## 技术栈关键点

- **全 ESM**：`"type": "module"`，所有包都是 ESM，不能有 CJS-only 导出。
- **pnpm workspaces**：需要 Node >= 24.9，pnpm 11.28.5。
- **TypeScript**：`strict: true`，严格禁止随意 `any` / `as unknown`。
- **Monorepo 分面编译**：Host 面 和 Client 面 分开编译（见 `tsconfig.host.json` / `tsconfig.client.json`）。
- **测试**：vitest 为主，分成单元、e2e、snapshot、expected、web 等多种配置。

## 运行方式

```sh
# 从 npm 直接跑（启动 Web UI，默认 http://127.0.0.1:3080）
npx @deepseek-ai/dsh web

# 从源码跑
pnpm install
pnpm run build       # 准备构建产物
pnpm dsh web         # 用产物启动，不重新构建
```

应用只能通过命名的 `dsh` profile 启动（`web`、`headless`、`sdk`、`sdk-minimal`、`acp`），不允许用包的 bin 或裸 Cordis 树直接启动。
